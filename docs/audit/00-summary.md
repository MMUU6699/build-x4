## 2. Root causes, in priority order

1. **History is structurally empty.** Every new conversation is a temporary draft; nothing promotes it; temporary rows are excluded from the drawer and never persisted. The Supabase `conversations`/`messages` tables also lack DML grants, so even promoted rows cannot be read/written.
2. **The drawer hides half the product.** It filters by the active mode, so Chat mode never shows Work and Work mode never shows Chat.
3. **Work is forced into the computer.** `tool_choice=any` until a notify call, a prompt that says a plain answer does not finish, and an eager `ensureSandbox()` before the first model call. A greeting cannot be a direct answer.
4. **The server trusts anonymous JWTs.** `chat` and `daytona-workspace` only check that a user exists; neither rejects `is_anonymous`.
5. **The DB grants are missing.** Live ACLs confirm `service_role`/`authenticated` have only `Dxtm` on the six core tables; this is the exact `permission denied for table workspaces` cause.
6. **The UI lies.** Fake developer profile, fake `Authenticated user session`, fake sheet footer, simulated Chat chunking, raw error dumps.
7. **The release is not signed.** No release keystore; earlier APK debug-signed; broad permissions.

## 3. Phase 1 execution order (after this file)

1. Explicit-grant migration + apply + verify with a real query/function call.
2. Promote drafts on first send (Chat and Work), map `mode` from Supabase, unify the drawer list with a Work badge, set Work conversation titles.
3. `AuthService` + real auth/profile screens; real drawer card; gate Work on `signedIn`; preserve draft; server 403 for anonymous Work.
4. Lazy sandbox + `tool_choice=auto` + direct-answer prompt + zero Daytona for greetings.
5. SSE streaming + thinking/reasoning/tool indicators + `Worked for Ns`.
6. Structured errors + friendly UI + retry.
7. Local-first history fallback and tests.
